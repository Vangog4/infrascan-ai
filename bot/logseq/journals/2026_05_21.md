- # Сессия 2026-05-21 — Бэклог улучшений InfraScan AI

## Контекст
  Оба проекта (InfraScan AI + AstroTara) приведены в рабочее состояние.
  InfraScan работает в режиме GEMINI_STUB=true (Gemini billing не подключён).
  EMPLOYEE_TG_IDS пустой — пользователь пришлёт ID инженеров позже.

## Бэклог — приоритизированный список

### 🔴 Сделать первым (высокий impact, низкий effort)

- [ ] **Пуши клиенту о статусе заявки**
  Клиент оставляет заявку и получает тишину. Нужно: при смене стадии задачи в Odoo бот
  отправляет уведомление пользователю — «Инженер назначен», «Инженер выехал», «Отчёт готов».
  Хук в `project_task.py` уже умеет посылать TG-сообщения. Нужно добавить `x_client_tg_id`
  в задачу и передавать при создании заявки из бота.

- [ ] **История отчётов `/myreports`**
  Результат анализа есть только в чате, нигде не хранится долго (Redis TTL).
  Нужна команда `/myreports` — последние 5 анализов: дата, объект, вердикт, кнопка "Скачать PDF".
  Хранить в новой таблице `bot_report` в Postgres (через Odoo модель или отдельно).

- [ ] **Пакеты анализов (микропокупки)**
  Вместо только Premium-подписки: «3 анализа за 300 Stars», «10 за 800 Stars».
  Инфраструктура Stars-платежей в `handlers/payments.py` уже есть.
  Нужна таблица `user_credits` и декоратор-проверка перед анализом.

- [ ] **Webhook вместо polling**
  `WEBHOOK_URL` и `webhook_path` в конфиге уже есть, endpoint в боте готов.
  Нужно: заполнить `WEBHOOK_URL=https://infrascan-ai.ru/bot/webhook` в `.env`,
  настроить в NPM проксирование `/bot/webhook` → `infrascan-ai_bot:8080`.

### 🟡 Второй приоритет (высокий impact, средний effort)

- [ ] **Сравнение «До / После»**
  Хранить последний анализ объекта (по user_id). При новом снимке — показывать дельту:
  было MEDIUM → стало LOW, аномалия −3°C. Killer-фича для повторных продаж.
  Требует: хранение истории анализов + prompt-дополнение для Gemini.

- [ ] **GPS-маршрут инженера**
  Кнопки «Выехал» / «Я на месте» в боте для инженера.
  Клиент получает пуш с ETA. Время фиксируется в задаче Odoo.
  Требует: добавить `x_client_tg_id` в `project.task`, новые FSM-состояния.

- [ ] **Автовыбор оптимального времени съёмки**
  Тепловизор эффективен при Δt ≥ 10°C. Бот через OpenWeatherMap смотрит прогноз
  для города клиента и советует лучший день/час. Инженер приедет когда надо.
  Требует: OpenWeatherMap API key + команда `/besttime <город>`.

- [ ] **Онбординг для новых клиентов**
  При первом `/start` — короткий тур: что умеет бот, пример анализа, CTA.
  Снижает отток. Требует: FSM-состояние `Onboarding`, 3 шага с фото-примерами.

### 🟢 Третий приоритет (стратегические фичи)

- [ ] **Реферальная программа**
  Аналог механики AstroTara (уже реализована). Клиент приглашает → получает бонусный анализ.
  УК на 20 квартир = скидка 30%. Нужна таблица рефералов и deep link `/start?ref=ID`.

- [ ] **Дайджест для B2B клиентов**
  УК/ЖКХ раз в месяц: сколько объектов проверено, дефекты, устранённые проблемы.
  PDF через Odoo report engine. APScheduler cron уже работает.

- [ ] **Серийный анализ (несколько фото — один отчёт)**
  Режим «Серия» — клиент присылает 3–5 фото разных стен, бот делает сводный отчёт.
  Требует: FSM с накоплением фото + aggregate Gemini prompt.

### 🔵 Долгосрочные (квартал+)

- [ ] **Прогноз деградации**
  Серия анализов одного объекта → тренд → «через 2 зимы плесень гарантирована».
  Нет аналогов у конкурентов. Требует накопления данных за 2–3 сезона.

- [ ] **WebApp с интерактивной картой тепла**
  Фото + цветовая карта аномалий, клики на зоны = пояснения.
  Vue/React. Данные из Gemini-анализа.

- [ ] **REST API для партнёров**
  Страховые, риелторы, застройщики. POST /analyze → JSON.
  Монетизация через API-ключи. Odoo уже умеет.
